Задача: развернуть браузерную игру Worms на моём сервере по адресу https://<домен>/worms — игра, аккаунты и рейтинг. Telegram не нужен.

Репозиторий: https://github.com/fatalbazuka/worms (ветка main)
Инструкция: DEPLOY.md, раздел «Игра по пути, а не в корне домена».

Данные (заполняю я):
- Сервер и SSH: <пользователь>@<хост>
- Домен: <домен> — уже указывает на этот сервер

Что сделать:
1. Зайди на сервер. Посмотри ОС, свободное место и кто держит порты 80 и 443 (`ss -ltnp`).
2. Если нет Docker с плагином compose — поставь официальным способом (docs.docker.com/engine/install), проверь `docker compose version`.
3. Склонируй репозиторий в /opt/worms (ветка main), `cp .env.example .env`, права 600. В .env: HTTP_BIND=127.0.0.1, HTTP_PORT=8080, остальное не трогай.
4. Дальше один из двух вариантов:
   а) Порты 80/443 держит nginx с сайтом этого домена — `docker compose up -d --build`, затем вставь в server { … } этого домена два блока location из deploy/nginx-subpath.conf, `nginx -t` и reload. Перед правкой покажи мне, какой файл и что именно меняешь.
   б) Порты 80/443 свободны — допиши в .env DOMAIN=<домен>, WORMS_PATH=/worms, CADDYFILE=Caddyfile.subpath и запусти `docker compose --profile https up -d --build`.
   Если порты держит что-то другое (Apache, Traefik, панель) — остановись и опиши мне, что нашёл.
5. Проверь и пришли вывод:
   - `docker compose ps` — api и web в статусе healthy;
   - `curl -sI https://<домен>/worms` → редирект на /worms/;
   - `curl -sI https://<домен>/worms/` → 200, text/html, сертификат валидный;
   - `curl -s https://<домен>/worms/api/health` → {"ok":true};
   - `curl -s -X POST https://<домен>/worms/api/register -H 'content-type: application/json' -d '{"name":"Проверка Деплоя","password":"check1234"}'` → в ответе token;
   - главная страница сайта https://<домен>/ работает как раньше.
6. Настрой ежедневную копию базы через cron (раздел «Копии базы» в DEPLOY.md) и запусти её один раз руками.
7. В конце пришли: адрес игры, что установил и что поменял на сервере, как обновлять (`cd /opt/worms && git pull && docker compose up -d --build`, с `--profile https` для варианта б).

Нельзя:
- `docker compose down -v` и любое удаление томов — там база игроков;
- менять код игры, коммитить и пушить в репозиторий;
- открывать наружу порты 3000 и 8080 — только 80/443;
- ломать или перенастраивать другие сайты и сервисы на сервере.

Если что-то идёт не по инструкции — остановись и пришли проблему с выводом команд, не импровизируй.
